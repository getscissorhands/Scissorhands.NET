# Support

## Documentation

Start with the [README](README.md) and
[documentation website](https://getscissorhands.app/docs/). For the current
development line, use the [vNext documentation handoff](docs/website-documentation.md)
and [migration guide](docs/website-documentation.md#upgrading-to-vnext).
The website may not yet include all vNext behavior.

The [sample guide](samples/ScissorHands.Sample/README.md) covers local preview
and static builds. The [Web package guide](src/ScissorHands.Web/README.md)
covers application setup and links to the Core, Theme, and Plugin guides.

## Bugs and Feature Requests

Search [existing issues](https://github.com/getscissorhands/Scissorhands.NET/issues)
before opening a new report. Use the
[bug report form](https://github.com/getscissorhands/Scissorhands.NET/issues/new?template=01-BUG-REPORT.yml)
for reproducible problems or the
[feature request form](https://github.com/getscissorhands/Scissorhands.NET/issues/new?template=02-FEATURE-REQUEST.yml)
for proposed improvements, including documentation gaps.

Include the package version or commit, .NET SDK and operating system, whether
the issue occurs in preview or build mode, and a minimal reproduction. Include
browser details when relevant. Remove credentials and private content from
configuration, logs, screenshots, and examples.

Support is provided through the project's public documentation and issue
tracker; no response-time guarantee is offered.

## Private Reports and Contributions

Report suspected vulnerabilities privately using [SECURITY.md](SECURITY.md).
For conduct concerns, use the enforcement contact in
[CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

To contribute a fix or documentation improvement, follow
[CONTRIBUTING.md](CONTRIBUTING.md). Published release notes are indexed in
[CHANGELOG.md](CHANGELOG.md).
